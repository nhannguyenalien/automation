API cho Gemini Chat và Google Flow

Một contract chung cho chat, ảnh và video: xong nhanh trả dữ liệu ngay; chạy lâu trả ID để client lấy kết quả sau.

Base URL

Bắt đầu nhanh

GET/health
curl "$BASE_URL/health"
Máy chạy API phải mở Chrome, đăng nhập Google Pro và bật extension. Job được lưu trên Turso nên không mất khi API restart và có thể dùng chung giữa nhiều máy. Funnel hiện đưa API ra Internet; hãy đặt API key nếu URL được chia sẻ.

Chat Gemini

Mặc định extension chủ động chọn 3.5-flash-lite. Đặt model thành 3.1-pro nếu cần.

POST/chat
curl -X POST "$BASE_URL/chat" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: chat-batch-UNIQUE_ID" \
  -d '{
    "prompt": "Viết 5 tiêu đề quảng cáo cho một khóa học AI",
    "model": "3.5-flash-lite",
    "newConversation": true
  }'

Gửi batch bằng "prompts": ["Câu 1", "Câu 2"]. Nếu xong nhanh API trả HTTP 200 với dữ liệu; nếu chưa xong trả HTTP 202 với id, Location và Retry-After. Nếu POST mất response, retry đúng payload với cùng key để nhận lại job cũ.

Text to image

POST/generate
curl -X POST "$BASE_URL/generate" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: image-request-UNIQUE_ID" \
  -d '{
    "prompt": "Một chú mèo máy ở Hội An, cinematic",
    "ratio": "16:9",
    "outputs": 1,
    "worker": "extension",
    "projectUrl": "https://labs.google/fx/vi/tools/flow/project/PROJECT_ID"
  }'

Mặc định một prompt tạo đúng một ảnh. Chỉ đặt outputs lớn hơn 1 khi thật sự muốn nhiều phương án. Một job nhận tối đa 100 ảnh; API xử lý ngầm tuần tự theo nhóm tiến độ 10 prompt. Giữ nguyên Idempotency-Key khi retry cùng một yêu cầu để API trả lại job cũ, không tạo thêm ảnh. Sau khi nhận id, chỉ dùng GET /jobs/:id để theo dõi.

Image to image

Upload ảnh gốc trước, sau đó dùng URL nhận được làm referenceImageUrl.

Upload ảnh tham chiếu

curl -X POST "$BASE_URL/assets" \
  -H "Content-Type: image/jpeg" \
  --data-binary @anh-goc.jpg

Kết quả có dạng { "url": "https://…/assets/…jpg" }.

Tạo ảnh từ ảnh gốc

curl -X POST "$BASE_URL/generate" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: image-edit-UNIQUE_ID" \
  -d '{
    "prompt": "Giữ nhân vật, đổi bối cảnh thành Hội An ban đêm",
    "ratio": "16:9",
    "outputs": 1,
    "worker": "extension",
    "projectUrl": "https://labs.google/fx/vi/tools/flow/project/PROJECT_ID",
    "referenceImageUrl": "URL_NHAN_DUOC_O_BUOC_1"
  }'

Image-to-image cũng nhận outputs: 1..4; bỏ field thì mặc định một ảnh cho mỗi prompt.

Video

POST/video
curl -X POST "$BASE_URL/video" \

  -d '{

Video dùng cùng contract HTTP 200/202 và cùng cơ chế lấy kết quả bằng GET /jobs/:id. URL hoàn tất nằm trong videos[].

Image-to-video

curl -X POST "$BASE_URL/video" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: image-video-UNIQUE_ID" \
  -d '{
    "prompt": "Chú công máy từ từ xòe chiếc đuôi phát sáng",
    "referenceImageUrl": "URL_NHAN_DUOC_TU_POST_ASSETS",
    "ratio": "16:9"
  }'

Có referenceImageUrl: extension dùng ảnh làm khung hình đầu; không cần ảnh cuối. Bỏ field này: chạy text-to-video. Mỗi prompt luôn tạo đúng một video.

Theo dõi và lấy kết quả

Contract chung: API chờ bằng event nội bộ, mặc định 20 giây cho chat và 2 giây cho ảnh/video, không poll Turso trong lúc chờ. POST trả HTTP 200 nếu đã xong; nếu chưa xong trả HTTP 202 + id. Với 202, gọi GET /jobs/:id theo retryAfterSeconds và dừng khi completed hoặc failed. Nếu POST mất response, retry đúng payload và cùng Idempotency-Key.
GET/jobs/:id
curl "$BASE_URL/jobs/JOB_ID"

queued: đang xếp hàng; running: extension đang xử lý; completed: đã xong toàn bộ; failed: thất bại sau retry. Ảnh thành công là các URL public S3 trong images[]; chat nằm trong response hoặc responses[].

{
  "id": "…",
  "status": "completed",
  "progress": 2,
  "total": 2,
  "images": ["https://s3a.schoolsai.work/…"]
}

Ví dụ JavaScript: tạo job và chờ kết quả

async function generateAndWait(prompt) {
  const idempotencyKey = crypto.randomUUID();
  const created = await fetch(`${BASE_URL}/generate`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Idempotency-Key": idempotencyKey
    },
    body: JSON.stringify({
      prompt,
      ratio: "16:9",
      outputs: 1,
      worker: "extension",
      projectUrl: "https://labs.google/fx/vi/tools/flow/project/PROJECT_ID"
    })
  });
  if (!created.ok) throw new Error(await created.text());
  let job = await created.json();
  if (job.status === "completed") return job.images;
  if (job.status === "failed") throw new Error(job.error || "Job failed");
  const { id } = job;

  const deadline = Date.now() + 15 * 60_000;
  while (Date.now() < deadline) {
    await new Promise(resolve => setTimeout(resolve, 4000));
    const response = await fetch(`${BASE_URL}/jobs/${id}`);
    if (!response.ok) throw new Error(await response.text());
    job = await response.json();
    if (job.status === "completed") return job.images;
    if (job.status === "failed") throw new Error(job.error || "Job failed");
  }
  throw new Error(`Timeout khi chờ job ${id}`);
}

Vận hành ổn định

  • Khởi động bằng npm run api; lệnh tự đọc file .env.
  • Cấu hình TURSO_DATABASE_URL và TURSO_AUTH_TOKEN. Turso là nguồn dữ liệu queue chính.
  • Giữ đúng ba tab cố định: Gemini Chat, Flow Image và Flow Video. Extension bấm Hình ảnh/Video ở sidebar, đồng thời xác nhận loại composer trong popup vì sidebar chỉ lọc thư viện.
  • Không đóng Chrome hoặc tắt extension khi job đang chạy.
  • Restart API sẽ tự đưa job đang chạy về hàng đợi.
  • FLOW_MAX_QUEUED mặc định 100. FLOW_IMAGE_MAX_RETRIES mặc định 0; FLOW_MAX_RETRIES mặc định 2 cho các loại khác.
  • Client POST một lần: HTTP 200 thì dùng kết quả ngay; HTTP 202 thì lưu id và poll bằng GET. Dùng Idempotency-Key cho mọi job chat, ảnh và video.
  • /health trả số job queued/running/completed/failed và trạng thái Turso.
  • Vì Funnel public Internet, nên bật FLOW_API_KEY trước khi dùng production hoặc chia sẻ URL.
